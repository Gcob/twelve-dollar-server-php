## Assumptions checked

- **Pss from the probe:** a `--pid host --cgroupns host` container read `/proc/<pid>/smaps_rollup` of a process in
  another container (`Pss: 501 kB`) as root, with default capabilities. The phase 3 memory reading works with the
  probe as it is.
- **The caches proof (scope 4):** feasible as written. `TcpConnection`'s constructor needs only an `EventInterface`
  and a stream (`Connection/TcpConnection.php:428-446`, so the Select loop does, without ext-event).
  `parseGet()` caches only a non-empty query string, and `parsePost()` only a non-multipart body
  (`Protocols/Http/Request.php:538-598`): the plan's "with a query string", "with a form body" are the right inputs.
- **Scope 3's one-at-a-time client:** blocking connect, request and read need no select loop, so scope 3 no longer
  depends on scope 4's ext-event. The non-blocking `feof` sweep finds closed sockets. At the fd limit the kernel
  completes the connection and the read times out, which matches the "timeout" reason. Back-to-back runs: the side
  that closes first holds the `TIME_WAIT`. Client-side ones block `bind()` on the same source address, and the
  plan's "wait or use the next block" covers them.
- **Predictions 7 and 8 (revised at 16:44):**
  - The ranges match prior art (18 to 42 KiB). The arithmetic holds: about 34 KiB per connection reaches 2 GiB near
    60k.
  - Each prediction can clearly hold or fail: OOM or not, a count between 65,000 and 65,535, a slope range.
  - The judging rule (median of 3; a percentage relative to the named number) removes the ambiguity in 2 and 4.
- **D21's phpize layer:** `ext/pcntl` and `ext/sockets` build as shared extensions from the pinned php.net tarball.
  D13's configure line (`install-php-src.sh:63`) is untouched.

## 🟡 MINOR

1. **Scope 2 first: the backlog and `TCP_NODELAY` are "recorded", but nothing says how,** and scope 5's "check it in the
   conformance output" can't work: a client can't see the server's `TCP_NODELAY`. Suggested: each server prints its
   backlog and `TCP_NODELAY` at boot, and the harness copies that line into the JSON.
   - Workerman and DIY read the option back with `socket_get_option` on `socket_import_stream()` of the listening
     socket.
   - Swoole can only print its configured settings: `Server::getSocket()` needs Swoole built with sockets, and the
     images' Swoole isn't (`install-php-src.sh:82`).
2. **Scope 2 first: "peak memory under load" (scope 7's table) has no Pss source.** Pss is a snapshot, with no
   high-water mark, while the shared rule wants Pss and `memory.current` "everywhere a memory number is reported".
   Suggested for `macro.sh`:
   - sample the Pss sum and `memory.current` with the connections at 1/4, 1/2 and 3/4 of the run, and keep the
     largest;
   - keep `memory.peak` and VmHWM as they are.
3. **Scope 2 first: `other_containers` now means containers "that aren't the lab's"** (shared rules). A lab run started
   from the main checkout during a scope 7 measurement (a `check.sh` smoke, a `conns.sh`) would not count as noise.
   The full review's wording, "not this run's own containers", catches it.
4. **`--ext` order:** PECL `event` builds with its sockets support by default and then needs `sockets` loaded first.
   Scope 5 lists `--ext pcntl --ext sockets --ext event` in that order, but scope 6 doesn't list DIY's. Write
   `--ext sockets --ext event` for DIY, or build `event` without its sockets support.
