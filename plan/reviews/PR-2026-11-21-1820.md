## Description de la PR

**Résumé**

Le labo de la phase 3 : un handler commun, trois serveurs (Swoole, Workerman avec ses 5 caches de requêtes retirés ou non, et un serveur maison sur ext-event), un test de conformité HTTP et un test de connexions inactives. Il ne mesure rien encore : la comparaison vient dans un commit à part, sur une VM Docker silencieuse.

```diff
 lab/
+  servers/handler.php              le même handler pour les trois
+  servers/bake-swoole.php
+  servers/bake-workerman.php       WORKERMAN_TREE=nocache|stock
+  servers/bake-diy.php             boucle ext-event et parseur HTTP maison
+  conformance.sh                   HTTP/1.1 en sockets bruts
+  conns.sh                         connexions inactives, max et mémoire par connexion
+  images/install-extras.sh         pcntl, sockets, event, deux arbres Workerman
~  macro.sh                         --ext, --env, --label, mémoire sous charge, other_containers
~  check.sh                         32 vérifications, dont shellcheck épinglé
```

**Décisions**

- **PHP 8.5, ext-event pour Workerman et le serveur maison :** `stream_select` plafonne à 1,024 descripteurs, ce qui fausserait le test de connexions; même boucle pour les deux, donc seule la couche HTTP diffère.
- **Chaque runtime garde ses propres en-têtes de réponse :** moins d'octets d'en-tête fait partie de ce qu'un runtime peut gagner; les résultats noteront les octets exacts.
- **Backlog 4,096 et `TCP_NODELAY` pour les trois :** le défaut de PHP (32) classerait le harnais, pas le runtime.
- **Le max de connexions est compté par le client :** les connexions qui ont eu leur réponse et sont encore ouvertes; `/proc/net/tcp` sert de recoupement, et une erreur côté client fait échouer le run au lieu de passer pour un plafond.
- **L'écriture partielle du serveur maison est testée sur une paire de sockets :** sur loopback, les tampons grossissent jusqu'à des mégaoctets, donc un test de bout en bout peut passer sans jamais écrire en partie.
- **Les 5 caches de Workerman sont supprimés par un patch qui fait échouer le build :** s'il ne s'applique pas ou s'il reste un `static`, l'image ne se construit pas.

**Changements**

- Handler commun et trois serveurs de bake-off, avec la ligne `socket:` (backlog, `TCP_NODELAY`) copiée dans le JSON des mesures.
- `conformance.sh` : 8 cas (routes, erreurs, keep-alive, pipelining, requête coupée, corps puis réutilisation, octets de réponse).
- `conns.sh` : paliers jusqu'à 66k connexions, rotation des adresses source, pente de Pss et de `memory.current`, cause d'arrêt nommée.
- Images : `pcntl`, `sockets`, `event` 3.2.0 et Workerman 5.2.4 (deux arbres), tout épinglé par sha256.
- `macro.sh` : `--ext`, `--env`, `--label`, Pss sous charge, `other_containers`; `posts.js` pour `GET /posts/:id`.
- `check.sh` passe de 18 à 32 vérifications; shellcheck tourne dans Docker, image épinglée.

**Preuves**

- `bash lab/check.sh` : 32/32 ok sur le dernier commit (environ 2 minutes).
- Test du parseur maison : 30 cas ok, dont la requête coupée à chaque position d'octet.
- Test d'écriture partielle : 4 cas ok (640 075 octets, 420 811 encore en tampon après la première écriture).
- `workerman-caches.php` : 5 caches remplis sur `stock`, 5 vides sur `nocache`.
- Sur une VM occupée (pas des mesures) : 7,000 req/s, 20 s, VALID pour les quatre serveurs sur `/noop` et `GET /posts/:id`; 65,522 connexions tenues sur Swoole avant la limite de descripteurs.

**Ce qu'on a appris**

- Workerman garde une connexion HTTP 60 s quoi que disent `Connection: close` ou l'en-tête de réponse : un client qui lit jusqu'à la fermeture attend une minute.
- Un `Response` de Workerman n'ajoute pas d'en-tête `Server` (seulement `Connection`, `Content-Type`, `Content-Length`).
- `fread` sur un socket PHP rend au plus 8 192 octets, quelle que soit la longueur demandée; un test qui appelle `onReadable()` une fois par écriture doit boucler.
- La plage de ports éphémères de la VM est 55000-65535 (10 536 ports), pas celle par défaut de Linux : 66k connexions demandent 7 adresses source.
